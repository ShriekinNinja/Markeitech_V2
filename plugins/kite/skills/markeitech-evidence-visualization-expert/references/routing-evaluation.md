# Routing Evaluation

Use these cases when validating advisor discovery and cross-specialist ownership. `PENDING` cases
require an installed-plugin forward test in a fresh thread; static inspection alone is insufficient.

| Request | Expected route | Boundary or stop condition | Status |
|---|---|---|---|
| Audit whether a 9D.5D entity chart preserves canonical identity, timestamps, health, and revision state | Delegate to `markeitech_evidence_visualization_advisor` | Advisor may recommend visual acceptance only; it must not change entity semantics | PENDING |
| Review chart scale, visible window, multi-horizon layout, annotations, non-color encoding, keyboard access, or visual baselines | Delegate to `markeitech_evidence_visualization_advisor` | Keep source resolution, analytical horizon, session, profile, and limitations explicit | PENDING |
| Review browser render responsiveness, long tasks, hidden-tab rendering, or visual resource disposal | Delegate to `markeitech_evidence_visualization_advisor` for browser acceptance | Route process, worker, queue, serialization, gateway, and core-runtime mechanics to their specialists | PENDING |
| Define an entity, metric, evidence-health category, market-structure relationship, support/resistance meaning, or trading signal | Do not route to this advisor | Use the relevant analytical, evidence, or market-structure specialist | PENDING |
| Choose WebSocket or IPC semantics, snapshot/delta ordering, deduplication, coalescing, retry, overflow, backpressure, or resnapshot policy | Do not route to this advisor | Event-driven architecture coverage is required; apply the router's missing-coverage gate when absent | PENDING |
| Choose a gateway process, cache owner, frontend framework, state store, worker topology, deployment model, dependency, or authentication boundary | Do not route to this advisor | Route topology to architecture and executable behavior to Python, security, or frontend specialists; apply missing-coverage gates | PENDING |
| Decide what Sir Loke must reason about, cite, rank, omit, summarize, or abstain from | Do not route to this advisor | Live-agent governance coverage is required; visualization consumes only an approved output contract | PENDING |
| Decide how an approved Sir Loke contradiction, abstention, citation, uncertainty, or supersession field should appear visually and accessibly | Delegate to `markeitech_evidence_visualization_advisor` | Preserve canonical meaning; do not redefine the field or its materiality | PENDING |
| Create brand identity, marketing artwork, or decorative visuals unrelated to canonical evidence | Do not route to this advisor | Use the appropriate design or image workflow | PENDING |

## Fresh-Thread Forward Test

After the plugin cachebuster is refreshed and the plugin is reinstalled, verify in a fresh thread:

1. A consequential financial-chart or visual-acceptance request discovers this skill and delegated
   advisor without requiring Markeitect to name it.
2. A transport, gateway, entity-semantics, or Sir Loke-governance request does not route here.
3. The custom agent loads `$kite:markeitech-evidence-visualization-expert` and produces a
   task-proportionate Projection Integrity Matrix.
4. Missing event-driven, frontend-architecture, or live-agent-governance coverage produces the
   router's missing-coverage gate instead of generic design advice.
5. The advisor recommends visual acceptance or rejection but does not claim final review authority.
