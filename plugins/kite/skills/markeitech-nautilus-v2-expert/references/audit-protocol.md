# Independent Nautilus Alignment Audit

Use this protocol for a complete read-only audit after implementation work is ready. The auditor evaluates the system that exists, not the architecture the builders intended.

## Independence

When delegation is available, use a fresh high-capability agent that did not design or implement the reviewed batch. Give it the repository authority files, this skill, the target scope, and raw evidence. Do not disclose expected findings, suspected defects, preferred fixes, or desired conclusions.

The auditor may inspect code, configuration, tests, installed packages, public stubs, documentation, logs, and approved database evidence. It must not edit, commit, push, run connected services, alter databases, or make architecture decisions.

## Audit Sequence

1. Establish branch, worktree, authority documents, implemented status, and explicit scope.
2. Refresh nightly guides and API; establish the installed version.
3. Build the native subsystem census before reviewing custom implementations.
4. Produce the Nautilus Alignment Matrix for every consequential capability.
5. Trace provider demand through adapter, engine, cache, actor, analysis, semantic state, persistence, and projection.
6. Review indicators for native duplication, update lifecycle, initialization, reset semantics, formula correctness, fidelity, and acceptance evidence.
7. Review persistence for ownership, data class, recovery meaning, retention, idempotency, and overlap with native facilities.
8. Review callback safety, queues, resources, partial failure, retries, late work, and shutdown.
9. Review evidence honesty, UTC and session semantics, contract identity, configuration ownership, and optimization boundaries.
10. Run focused offline tests only when they can validate a concrete candidate. Treat their result as scoped evidence.

## Reporting

Lead with concrete findings ordered by severity. For each finding include:

- affected file and tight line reference;
- observed behavior or contract;
- evidence layer;
- impact and realistic failure mode;
- native capability or accepted boundary involved;
- smallest corrective direction;
- missing acceptance evidence.

Continue after the first finding. Separate confirmed defects, architecture misalignments, documentation drift, validation debt, recommendations, and unknowns. If no defect is found, say so and identify residual risk and untested connected behavior.

The primary agent must independently verify important claims before asking Markeitect to approve changes.
